# Veil_lore

[![canon](https://github.com/bfunkmcgee/Veil_lore/actions/workflows/canon-ci.yml/badge.svg)](https://github.com/bfunkmcgee/Veil_lore/actions/workflows/canon-ci.yml)

Canon repository for **The Veil** — world bible, structured canon ledger, and
dramatized scenes, wrapped in a validation toolchain. Every lore change is made in
an authoritative source, rebuilt deterministically, and checked by a harness of
blocking invariants; CI enforces the same loop on every pull request.

## Layout

| Path | What it is |
|---|---|
| [`codex/`](codex/) | The Veil Codex package — three hand-authored sources, generated reference volumes, and the build/validation toolchain. See [`codex/README.md`](codex/README.md) (generated) for the live canon status line and precedence order. |
| [`docs/`](docs/) | Strategy documents: the [SANDLINE integration plan](docs/SANDLINE_Canon_Integration_Plan.md) and [ThinShot → SANDLINE roadmap](docs/ThinShot_to_SANDLINE_Roadmap.md) for the sister game repo [`bfunkmcgee/ThinShot`](https://github.com/bfunkmcgee/ThinShot). |
| [`CONTRIBUTING.md`](CONTRIBUTING.md) | The edit loop, the canon-ruling recipe, and how to read a CI failure. |
| [`CLAUDE.md`](CLAUDE.md) | The same contract, written for Claude sessions working in this repo. |

## Quickstart

```bash
cd codex
python3 build.py --no-docx   # regenerate targets (Python 3.10+, stdlib only)
python3 harness.py           # expect: INVARIANTS: PASS / LINT: clean
```

## The rules in one paragraph

Edit only the three sources (`Veil_Unified_World_Bible.md`,
`veil_canon_ledger.json`, `Veil_Scenes.md`); everything else in `codex/` is
generated by `build.py` and byte-checked by `harness.py` — including
`codex/README.md`, so this file here at the root is the repo's front page, not
that one. Canon changes require a ruling in the ledger **and** a matching
changelog entry (via `add_ruling.py`). DOCX renditions are never committed: the
`docx` CI job (manual run or a `v*` tag) builds them with pandoc and uploads the
`veil-codex-docx` workflow artifact.
